## 3-3 실측 기록 (본인 환경)

**실습 환경:** Ubuntu 22.04 WSL2 / Python 3.12.15 / DuckDB

| 항목 | CSV | Parquet(zstd) | 배율 |
|---|---:|---:|---:|
| 파일 크기 | 40.56 MiB | 9.82 MiB | 4.13배 압축 |
| 집계 질의 | 0.1051초 | 0.0045초 | 23.3배 빠름 |
| 한 열만 읽기 | 0.086초 | 0.0014초 | 약 61.4배 |
| 다섯 열 읽기 | 0.106초 | 0.0100초 | 약 10.6배 |

### 압축 방식 비교

| 압축 방식 | 파일 크기 | 조회 시간 |
|---|---:|---:|
| zstd | 9.8 MiB | 0.004초 |
| snappy | 15.9 MiB | 0.003초 |
| gzip | 10.6 MiB | 0.004초 |

### 파티션 조회 비교

- 파티션 파일: 0.0017초
- 단일 Parquet 파일: 0.0025초
- 파티션 조회 약 1.47배 빠름

### 거꾸로 나온 측정

`COUNT(*)`가 0.0008초로 한 열 집계(0.0014초)보다 빨랐다.

이유: DuckDB가 불필요한 열 읽기를 제거하고 Parquet 파일의 메타데이터를 활용해 행 수를 계산할 수 있기 때문이다.

### 결론

대용량 분석에서는 CSV보다 Parquet를 중간 산출물로 활용하면 저장 공간과 처리 시간을 줄일 수 있으며, 필요한 열과 파티션만 선택적으로 읽도록 설계하는 것이 중요하다.

*실측 수치는 실행 환경과 반복 측정 시점에 따라 달라질 수 있다.*
