# 3주차 산출물 — 데이터 품질 리포트

## 1. 대상
- 원본: orders.csv (1,015행), 고정 시드로 생성한 실습 데이터
- 정제 결과: orders_clean.parquet (1,000행)
- 파이프라인: clean_orders.py
- 역할: DuckDB로 읽고 Pandas로 정제·검증 후 Parquet 저장

## 2. 품질 지표 전후 비교

| 지표 | before | after |
|---|---:|---:|
| 행 수 | 1,015 | 1,000 |
| order_id 중복 | 15 | 0 |
| price 결측 | 30 | 0 |
| price 결측률 | 2.96% | 0.00% |
| category 고유값 | 5 | 4 |

행 수 감소율은 약 1.5%이며, 중복 제거에 따른 변화다.

## 3. 처리 내용과 근거

| 문제 | 처리 | 근거 |
|---|---|---|
| category 앞뒤 공백 20건 | str.strip() | 같은 식품 분류가 공백 때문에 별도로 집계됨 |
| order_date 타입 | pd.to_datetime() | 읽는 도구에 따라 달라질 수 있는 날짜 형식을 통일 |
| order_id 중복 15건 | 주문번호 기준 첫 행 유지 | 실습에서 추가한 중복 주문의 이중 집계를 방지 |
| price 결측 30건 | 중복 제거 후 중앙값 100,500원으로 보정 | 이상치 영향을 줄이는 실습 규칙 적용. 중복 포함 중앙값은 101,000원으로 달라 처리 순서를 고정 |
| 주문금액 | price × quantity로 amount 생성 | 보정된 가격을 반영해 금액을 계산 |

처리 순서: 공백 제거 → 날짜 타입 변환 → 중복 제거 → 결측 보정 → 금액 계산.

중앙값 보정은 추정이며 실제 판매 가격을 복원한 것은 아니다.

## 4. 고치지 않은 것
- 원본 orders.csv는 수정하지 않고 보관했다.
- 결측이 아닌 가격은 별도의 이상치 보정 없이 유지했다.
- 주문번호와 고객번호는 중복 행 제거 외에 값을 변경하지 않았다.

## 5. 검증
- 기준선: 원본에서 1,015행·중복 15건·가격 결측 30건·분류 5개 확인.
- 전후 비교: quality_report.csv에서 정제 후 1,000행·중복 0건·가격 결측 0건·분류 4개 확인.
- 멱등성: clean(raw)와 clean(clean(raw))의 행 수·내용 및 두 결과의 Parquet 재조회 비교가 모두 True.
- 순서 실험: 중복 제거 전후 중앙값이 101,000원과 100,500원으로 다름을 확인.
- 검사기 실험: 음수 가격과 미지 카테고리를 주입해 각각 1건 탐지.
- 최종본: 가격·수량 0 이하, 미지 카테고리, 주문번호 중복, 가격 결측 검사 통과. 종료 코드 0.
- DuckDB 교차 검증: 네 지표가 Pandas 보고서와 일치(True). 날짜 범위는 2026-06-01~2026-07-30.
- 결과 파일 삭제 후 재생성: 정제 Parquet 삭제 후 파이프라인과 품질 리포트를 재실행하고 교차 검증 통과.

최종 validate()에는 미래 날짜 검사가 포함되어 있지 않다.

## 6. 남은 과제
- 보정한 가격을 식별하는 표시 열을 추가한다.
- 가격·수량·날짜·주문번호의 추가 결측 및 타입 오류 검사를 보완한다.
- 실제 업무에서는 같은 주문번호의 내용이 다를 때 남길 기록의 기준을 정한다.
- 실제 매출 보고에는 원본 가격 확인과 추정값 분리 정책이 필요하다.
